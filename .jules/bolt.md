## 2023-10-27 - [Optimize Levenshtein Distance Calculation]
**Learning:** In the Node.js backend, synchronous string matching algorithms like `levenshteinDistance` run single-threaded and block the event loop. The original implementation used a 2D matrix (`const matrix = []`), resulting in $O(N \times M)$ memory allocations and massive Garbage Collection (GC) overhead during bulk matching tasks.
**Action:** Always optimize dynamic programming matrix calculations in high-frequency Node.js loops by using an $O(N)$ 1D array approach combined with a globally shared `Uint16Array` buffer for standard lengths. Include a dynamic allocation fallback for inputs that exceed the buffer's maximum length.
## 2023-10-27 - [Optimize Jaccard Similarity Bigrams]
**Learning:** In the Node.js backend, generating bigrams for string similarity traditionally involves frequent calls to `s.substring()`, which creates numerous short-lived string objects and triggers high Garbage Collection (GC) overhead in tight loops (like iterating over thousands of search results).
**Action:** When computing similarities based on short n-grams, especially bigrams, bypass string allocation entirely by packing adjacent 16-bit character codes (via `s.charCodeAt()`) into a single 32-bit integer: `(s.charCodeAt(i) << 16) | s.charCodeAt(i + 1)`. Storing these integers in a `Set` offers a massive speedup (e.g., ~60%) with zero loss in accuracy.
