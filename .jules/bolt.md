## 2023-10-27 - [Optimize Levenshtein Distance Calculation]
**Learning:** In the Node.js backend, synchronous string matching algorithms like `levenshteinDistance` run single-threaded and block the event loop. The original implementation used a 2D matrix (`const matrix = []`), resulting in $O(N \times M)$ memory allocations and massive Garbage Collection (GC) overhead during bulk matching tasks.
**Action:** Always optimize dynamic programming matrix calculations in high-frequency Node.js loops by using an $O(N)$ 1D array approach combined with a globally shared `Uint16Array` buffer for standard lengths. Include a dynamic allocation fallback for inputs that exceed the buffer's maximum length.

## 2023-10-28 - [Extract Inline Regexes and Normalization Functions]
**Learning:** In the Node.js backend, defining complex regular expressions with the `/g` flag and normalization functions inline within Express route handlers or nested loops causes V8 to repeatedly allocate memory for these objects on every invocation. This leads to redundant Garbage Collection overhead and slows down request processing significantly, particularly for text-heavy operations like string matching.
**Action:** Always hoist commonly used normalization functions (e.g., `normalizeTitle`, `normalizeArtist`) to a shared module (like `server/utils.js`). Furthermore, pre-compile their corresponding regular expressions at the module level using standard `REGEX_` prefixes. Using `/g` regular expressions globally with `String.prototype.replace()` is safe in Node.js because the engine resets `lastIndex` automatically.
