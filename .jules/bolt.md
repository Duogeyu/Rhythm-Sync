## 2023-10-27 - [Optimize Levenshtein Distance Calculation]
**Learning:** In the Node.js backend, synchronous string matching algorithms like `levenshteinDistance` run single-threaded and block the event loop. The original implementation used a 2D matrix (`const matrix = []`), resulting in $O(N \times M)$ memory allocations and massive Garbage Collection (GC) overhead during bulk matching tasks.
**Action:** Always optimize dynamic programming matrix calculations in high-frequency Node.js loops by using an $O(N)$ 1D array approach combined with a globally shared `Uint16Array` buffer for standard lengths. Include a dynamic allocation fallback for inputs that exceed the buffer's maximum length.
## 2024-05-25 - Parallelize Backend I/O and Lookups
**Learning:** Sequential `for...of` loops with `await` in Express route handlers (like `/api/check`, `/api/admin/recent-logs`, and `/api/admin/stats`) significantly increase latency, as each operation (e.g., fetching game data, reading files, or looking up IP locations) must complete before the next begins. Synchronous file reads (`fs.readFileSync`) also block the Node.js event loop, further degrading performance.
**Action:** When aggregating data or performing I/O across arrays in backend routes, replace sequential `for...of` loops with `await Promise.all(array.map(async (item) => ...))`. Replace `fs.readFileSync` with `fs.promises.readFile` inside these parallel blocks. To ensure robustness, wrap individual operations in `try...catch`, return `null` on failure, and filter the final results (e.g., `results.filter(item => item !== null)`). Update dependent states (e.g., `foundInGames = Object.keys(matches).length`) *after* the `Promise.all` block to prevent race conditions.
