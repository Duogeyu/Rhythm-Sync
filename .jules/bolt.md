## 2025-03-08 - [Optimize Levenshtein Distance Calculation]
**Learning:** The previous implementation of `levenshteinDistance` in `server/index.js` used a 2D array, leading to O(M*N) space complexity and severe Garbage Collection pressure from allocating/deallocating thousands of 2D matrices per request during song matching. The backend also heavily uses fuzzy matching (`fuzzysort` and custom algorithms) and relies on the worker thread or node process executing many times per API hit, making inner-loop performance critical.
**Action:** Replaced the 2D matrix algorithm with an optimized 1D `Uint16Array` approach that takes only O(min(M, N)) space. To apply next time: for string comparisons running inside tight loops or processing arrays, avoid large structural allocations like nested arrays, and prefer flat Typed Arrays mapped to sliding windows.
