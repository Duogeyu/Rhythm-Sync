## 2024-05-18 - [Replaced O(n²) Fuse.js Matching with Linear Fuzzysort in Music Matching Engine]
**Learning:** Replaced the legacy `fuse.js` text matching engine within `server/match_worker.js` and `server/index.js` endpoints (`/api/match-all`, `/api/bot/query`) with `fuzzysort`. `fuse.js` executes computationally expensive nested O(n²) string algorithms on multi-field objects (title and artist mappings) causing synchronous event loop blocking and memory spikes during concurrent large-playlist requests. `fuzzysort` operates on precomputed linear O(n) memory buffers which bypasses these bottlenecks.
**Action:** When migrating from `fuse.js` to `fuzzysort` in Javascript backend servers, explicitly map/prepare objects containing targeted search strings beforehand, extract out `.obj.original`, and invert the negative scoring threshold using `Math.max(0, (fuzzyResult.score + 1000) / 1000)` to ensure legacy API score constraints matching (`score < 0.3` becoming `1 - normalizedScore < 0.3`) do not break frontend expectations.
