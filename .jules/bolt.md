## 2023-10-27 - [Optimize Levenshtein Distance Calculation]
**Learning:** In the Node.js backend, synchronous string matching algorithms like `levenshteinDistance` run single-threaded and block the event loop. The original implementation used a 2D matrix (`const matrix = []`), resulting in $O(N \times M)$ memory allocations and massive Garbage Collection (GC) overhead during bulk matching tasks.
**Action:** Always optimize dynamic programming matrix calculations in high-frequency Node.js loops by using an $O(N)$ 1D array approach combined with a globally shared `Uint16Array` buffer for standard lengths. Include a dynamic allocation fallback for inputs that exceed the buffer's maximum length.
## 2026-06-19 - [Extract and Pre-compile Inline Regex Normalization Functions]
**Learning:** Defining functions containing complex regex operations inline within high-traffic routes or loops (like `normalizeTitle` and `normalizeArtist` in `server/index.js`) forces the V8 engine to repeatedly allocate memory and recompile the regex literals on every invocation, causing significant garbage collection pauses and CPU spikes.
**Action:** Always hoist performance-critical regexes to module-level constants (e.g., in `server/utils.js`) using prefixes like `REGEX_` and import the refactored, stateless functions directly. This ensures memory stability and immediate O(1) retrieval during repetitive looping operations.
