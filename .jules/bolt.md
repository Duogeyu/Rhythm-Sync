## 2023-10-27 - [Optimize Levenshtein Distance Calculation]
**Learning:** In the Node.js backend, synchronous string matching algorithms like `levenshteinDistance` run single-threaded and block the event loop. The original implementation used a 2D matrix (`const matrix = []`), resulting in $O(N \times M)$ memory allocations and massive Garbage Collection (GC) overhead during bulk matching tasks.
**Action:** Always optimize dynamic programming matrix calculations in high-frequency Node.js loops by using an $O(N)$ 1D array approach combined with a globally shared `Uint16Array` buffer for standard lengths. Include a dynamic allocation fallback for inputs that exceed the buffer's maximum length.

## 2023-11-09 - [Fuzzysort Performance Over Fuse.js]
**Learning:** In the Node.js backend, synchronous string matching over large datasets (e.g., arcade song databases against user playlists) creates substantial blocking loops and latency when using `Fuse.js`. `fuzzysort` offers roughly a ~7x speedup on these large arrays because it has lower object instantiation overhead and can heavily cache string states when its `.prepare()` function is used prior to the loop.
**Action:** When switching to `fuzzysort` to optimize fuzzy-matching loops, always keep the source objects in a separate nested object (e.g. `{ original: s, preparedTitle: fuzzysort.prepare(s.title) }`) during `.prepare()`. This avoids leaking the large internal structures of the Fuzzysort prepared instances into the final payload when matching results are serialized as JSON. Also, normalize Fuzzysort's native negative scoring format back to 0-1 logic, keeping the expected bounds.
