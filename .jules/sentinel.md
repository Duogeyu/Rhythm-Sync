## 2024-03-17 - Validate Dynamic Route Parameters in Express to Prevent Path Traversal
**Vulnerability:** Express endpoints reading route parameters (like `id` or `filename`) directly into `path.join` or `fs` functions are vulnerable to Path Traversal if the parameters contain `..` or `/`. Express automatically URL-decodes `%2f` back into `/`, which bypasses route matching and allows payload like `../../etc/passwd`.
**Learning:** We cannot assume the Express route string matching limits characters, especially when using URL encoding. Route parameters passed to the file system must be explicitly sanitized, checking for directory traversal characters (`..`, `/`, `\`, `\0`).
**Prevention:** Implement an `isSafeFilename` function to validate all parameters that determine file paths. It should reject filenames containing dangerous traversal characters instead of just enforcing alphanumeric characters to avoid breaking features that need hyphens, spaces, or brackets. Return a 400 Bad Request if validation fails.
