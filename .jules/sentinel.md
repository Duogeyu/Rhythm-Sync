## 2024-05-31 - [SSRF bypass via dns rebinding and unvalidated Axios parameters]
**Vulnerability:** A critical SSRF vulnerability existed in the `/api/covers/:gameId/:fileName` endpoint where `axios.get(req.query.url)` was executed directly. This allowed attackers to request internal resources (e.g. `http://127.0.0.1:3002/api/admin/stats`). Furthermore, simply parsing the URL via `new URL()` does not mitigate TOCTOU (Time of Check to Time of Use) DNS rebinding attacks.
**Learning:** Node.js `http`/`https` modules and Axios evaluate hostnames differently. Since Node.js does not trigger `dns.lookup` when directly connecting to an IP string, any static validation must explicitly check for IP strings. For hostnames, `dns.lookup` must be overridden in the `httpAgent`/`httpsAgent` so that the IP resolution is validated *after* DNS occurs but *before* the socket connects. Additionally, Open Redirect vulnerabilities often manifest in `catch` blocks that redirect to unvalidated user input (e.g., `res.redirect(originalUrl)`).
**Prevention:** For outbound HTTP requests, implement custom `http.Agent` and `https.Agent` Singletons with a patched `lookup` function that explicitly rejects resolved internal IPs (`0.0.0.0`, `127.x.x.x`, `10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`, `::1`, `fc00:/7`). Also apply static URL parsing validation to reject `localhost` and immediate IP literals. Lastly, ensure error routes fail securely (e.g., `res.status(400)`) instead of falling back to untrusted user-controlled redirects.
