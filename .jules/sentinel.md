## 2024-04-10 - Express App.param Path Traversal Protection
**Vulnerability:** The application was vulnerable to Path Traversal in multiple file-serving endpoints (e.g., `/api/covers/:gameId/:fileName`, `/api/random/image/:id`, `/api/bot/result/:id/image`, `/api/share/:id/image`, `/api/share/:shareId`) because Express route parameters (`req.params`) were not validated or sanitized before being evaluated by `path.join()` or `fs` methods.
**Learning:** Even when building internal/proxy APIs, user-supplied dynamic route parameters must be explicitly validated. Express decodes URL parameters (e.g., `%2f` to `/`), allowing traversal payloads to bypass basic route matching and trigger file system access vulnerabilities.
**Prevention:** Always implement a central validation mechanism, such as `app.param(['id', 'fileName', 'gameId', 'shareId', 'sessionId', 'shortId', 'uid', 'ip'], validationMiddleware)`, to consistently apply security checks like an `isSafeFilename` test across all endpoints that interact with the local filesystem, ensuring they reject illegal characters and traversal sequences (e.g., `..`, `/`, `\`) before reaching the route handlers.
