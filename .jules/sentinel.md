## 2026-04-20 - Global Path Traversal Protection
**Vulnerability:** Multiple API endpoints (`/api/covers/:gameId/:fileName`, `/api/bot/result/:id`, `/api/random/image/:id`, etc.) use user input directly in `path.join` without path traversal validation.
**Learning:** `req.params` parameters must be validated to prevent directory traversal (`..`, `/`, `\`) before being used in file system operations.
**Prevention:** Implement a global `isSafeFilename` middleware using `app.param()` to automatically reject any unsafe paths across all endpoints.
## 2026-04-20 - Global SSRF Protection via DNS Lookup Proxy
**Vulnerability:** External fetch features like `/api/covers/:gameId/:fileName` allowed Server-Side Request Forgery (SSRF) and Open Redirects because they blindly fetched any provided `url` without validating if the resolved IP was internal (e.g., `127.0.0.1`, AWS Metadata endpoints). They also returned redirects upon fetch failures.
**Learning:** Checking hostnames or URLs against IP blocklists before fetching is insufficient because of DNS rebinding and `localhost` mappings. The most robust SSRF defense in Node.js HTTP clients like `axios` is attaching custom `http.Agent`/`https.Agent` instances that override the `lookup` parameter to intercept `dns.lookup` and reject private IP addresses natively at the network boundary.
**Prevention:** Always use a custom DNS lookup interceptor (like `safeHttpAgent` and `safeHttpsAgent`) combined with protocol/IP validations in proxy/download endpoints. Never fallback to `res.redirect(originalUrl)` in fetch catch blocks, as it opens a reliable Open Redirect vulnerability.
