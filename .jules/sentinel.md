## 2026-04-14 - Path Traversal Vulnerabilities via Dynamic Express Route Parameters
**Vulnerability:** Path Traversal via Express route parameters (`:fileName`, `:id`, etc.). An attacker could inject payloads like `..%2f..%2fpackage.json` into routes (e.g., `/api/covers/maimai/..%2f..%2fpackage.json`) which would be evaluated by `path.join()`, allowing them to read arbitrary files from the filesystem.
**Learning:** Express `req.params` values are automatically URL-decoded, meaning URL-encoded payloads like `%2f` (slash) will bypass simple route pattern matching and reach file system functions. Relying purely on client-side constraints or implicit directory structure is insufficient. Express 5.x allows array groupings for `app.param()` (e.g., `app.param(['id', 'fileName'], middleware)`) which makes it very efficient to apply global path traversal protections to common parameter names that are subsequently used in file operations.
**Prevention:** Always validate all user input, especially route parameters passed to filesystem APIs (`fs`, `path`). Use a robust filtering mechanism that rejects characters like `..`, `/`, `\`, and `\0` in filenames, but be careful not to block valid characters needed for IDs like `|` or `:`. Utilize `app.param()` to apply this validation globally before the request hits the vulnerable endpoints.
