## 2026-04-04 - Path Traversal Vulnerability in Express Route Parameters
**Vulnerability:** File-serving endpoints (e.g., `/api/covers/:gameId/:fileName`, `/api/random/image/:id`, `/api/bot/result/:id`) passed Express route parameters directly into `path.join()` or `fs` functions without proper sanitization. Express decodes URL parameters (e.g., `%2f` to `/`), allowing attackers to bypass route matching and trigger path traversal attacks when the parameter is evaluated by `path.join()`.
**Learning:** Even though route patterns like `:fileName` might seem safe because they represent a single path segment in the URL, Express URL-decodes the parameter *after* route matching. This means an attacker can use URL-encoded slashes (`%2f`) or dots (`%2e`) to traverse directories.
**Prevention:** Use `app.param()` to globally validate commonly targeted path parameters (e.g., `id`, `fileName`, `gameId`, `shareId`) against path traversal characters before they reach any route handler. A dedicated `isSafeFilename` utility can centrally manage this validation and block traversal characters like `..`, `/`, `\`, and `\0`.
