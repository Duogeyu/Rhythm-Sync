## 2024-05-24 - Path Traversal in File Serving Endpoints
**Vulnerability:** Multiple Express endpoints (e.g., `/api/covers/:gameId/:fileName`, `/api/bot/result/:id`, `/api/random/image/:id`, `/api/share/:id/image`, `/api/share/:shareId`, `/api/arcade-song/:gameId/:songId/audio`) used un-sanitized path parameters (`req.params`) to construct local file paths via `path.join()`. This allowed attackers to input payloads like `..%2f..%2fetc%2fpasswd` to access arbitrary files on the server.
**Learning:** Even simple file-serving APIs that retrieve static assets based on IDs or filenames are highly vulnerable if `req.params` variables are directly passed into file system methods like `fs.existsSync()`, `fs.readFileSync()`, or `path.join()` without validation.
**Prevention:** Implement a strict validation utility like `isSafeFilename` that explicitly blocks path traversal characters (`..`, `/`, `\`) and enforces a safe regex (e.g., `^[a-zA-Z0-9_.-]+$`). Always validate `req.params` inputs before using them in file operations.
