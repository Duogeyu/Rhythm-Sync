## 2026-04-20 - Global Path Traversal Protection
**Vulnerability:** Multiple API endpoints (`/api/covers/:gameId/:fileName`, `/api/bot/result/:id`, `/api/random/image/:id`, etc.) use user input directly in `path.join` without path traversal validation.
**Learning:** `req.params` parameters must be validated to prevent directory traversal (`..`, `/`, `\`) before being used in file system operations.
**Prevention:** Implement a global `isSafeFilename` middleware using `app.param()` to automatically reject any unsafe paths across all endpoints.

## 2026-06-17 - SSRF in Cover Downloading and Proxying
**Vulnerability:** The `/api/covers/:gameId/:fileName` endpoint and the `downloadAndCacheCover` function download user-supplied URLs via `axios.get` without validating the host. This allows Server-Side Request Forgery (SSRF), enabling an attacker to make the server perform HTTP requests to internal IP addresses (e.g., cloud metadata endpoints or loopback services). Furthermore, if the download failed, the endpoint redirected the client to the unvalidated URL, maintaining an Open Redirect vulnerability.
**Learning:** External URL downloads via proxies or caches must validate both the format of the URL and the resolution of the domain to prevent DNS rebinding and internal network requests. Standard URL parsing is insufficient because DNS resolution can still resolve external domains to internal IP addresses.
**Prevention:** Implement a custom `dns.lookup` function that explicitly checks resolved IP addresses against a comprehensive internal IP blocklist (including loopback, private ranges, IPv4-mapped IPv6, and cloud metadata IPs). Pass this custom lookup function into `http.Agent` and `https.Agent` singletons used in all external Axios requests. Also, ensure fallback redirects validate the URL to prevent Open Redirects.
